# PRD: strava_blamer

## Суть

CLI-утилита на Go для одного пользователя. Переименовывает активности Strava с названием по умолчанию («Morning Run», «Утренний забег»…) в ярлык по типу и содержанию тренировки.

## Правила переименования

- Обрабатываются только активности с `sport_type` `Run` и `Swim`. Остальные типы (`TrailRun`, `VirtualRun` и т. д.) пропускаются, их можно добавить позже.
- Переименовываются только активности с названием по умолчанию. Шаблоны названий поддерживаются на русском и английском. Названия, заданные пользователем, не трогаются никогда.
- Название заменяется целиком, только ярлыком. Описание не меняется.
- Признак обработки — само название. Если название не по умолчанию, активность считается обработанной. Отдельного хранилища и маркеров нет, повторный запуск ничего не ломает.

### Бег

| Условие | Название |
|---|---|
| дистанция строго > 16 км | `Long run` |
| иначе | `Junk run` |

Порог задаётся флагом `--long-run-km` (по умолчанию 16).

### Плавание

| Условие | Название |
|---|---|
| хотя бы один интервал ≥ 600 м | `Long swim` |
| иначе | `Junk swim` |

- Интервалы — это laps из `GET /activities/{id}/laps`.
- Laps с нулевой дистанцией (отдых) не учитываются.
- Если laps нет, вся дистанция считается одним интервалом.
- Порог задаётся флагом `--long-swim-interval-m` (по умолчанию 600).

## Команды CLI

Используется cobra. У всех команд есть флаг `--dry-run`: показать решение без изменений в Strava.

| Команда | Поведение |
|---|---|
| `check <id\|URL>` | Обработать одну активность, переименовать сразу |
| `sweep [--days 7]` | Обработать необработанные активности за последние N дней |
| `watch [--interval 1h] [--days 7]` | Долгоживущий процесс: первый обход сразу при старте, затем `sweep` каждые `--interval`. Ошибки пишутся в лог, процесс ждёт следующего тика |

## Логи

`log/slog`, текстовый формат, вывод в stdout.

- `info`: одна строка на каждую переименованную активность — id, старое название → новое.
- `debug`: пропущенные активности.
- `error`: ошибки получения или изменения активности.

## Авторизация

- `STRAVA_CLIENT_ID` и `STRAVA_CLIENT_SECRET` берутся из переменных окружения.
- Refresh token хранится в файле, путь задаётся флагом (в Docker — `/data/token.json`). Strava выдаёт новый refresh token при каждом обновлении, а старый сразу перестаёт работать, поэтому новый токен нужно сразу сохранять в файл.
- Если файла нет, токен берётся из `STRAVA_REFRESH_TOKEN` и сохраняется в файл.
- Нужные scopes: `activity:read_all` и `activity:write`.
- Первичное получение токена через OAuth описывается пошагово в README. Отдельной команды для этого нет.

## Сборка и запуск

Makefile:

| Цель | Действие |
|---|---|
| `build` | Собрать бинарник |
| `test` | `go test ./...` |
| `docker-build` | Собрать образ `strava_blamer` |
| `docker-run` | Запустить `watch` в контейнере `strava_blamer`: `--restart unless-stopped`, volume `strava_blamer_data:/data`, `--env-file .env`. Если контейнер уже существует, сначала удалить его (`docker rm -f`) |
| `docker-stop` | Остановить и удалить контейнер |
| `docker-logs` | Показать логи контейнера |

- Dockerfile двухэтапный: сборка на `golang:<версия>`, запуск на `gcr.io/distroless/static`, `CGO_ENABLED=0`.
- `.env` добавляется в `.gitignore`, в репозитории лежит `.env.example`.
- Push в registry и docker-compose не нужны.

## Код

- Путь модуля: `github.com/droneru/strava_blamer`.
- Структура:
  - `cmd/strava_blamer` — точка входа и команды cobra;
  - `internal/strava` — клиент API за интерфейсом, работа с токеном;
  - `internal/blame` — классификатор и шаблоны названий по умолчанию.
- Тесты:
  - табличные тесты для классификатора и шаблонов;
  - фейковый клиент для `check` и `sweep`.

## Ограничения Strava API (учтены в дизайне)

- У активностей нет тегов и произвольных полей. Через `PUT /activities/{id}` можно менять только `name`, `description`, `commute`, `trainer`, `hide_from_home`, `sport_type` и `gear_id`.
- Флага «название по умолчанию» в API нет, поэтому такие названия определяются по шаблонам.
- `GET /athlete/activities` возвращает название, тип и дистанцию, но не описание и не laps.
- Для плавания нужен отдельный запрос laps на каждую активность.
- Лимиты запросов на чтение: 100 за 15 минут и 1000 в сутки. Для запуска раз в час с окном 7 дней этого хватает с запасом.
- Бассейн и открытую воду API не различает: оба — `Swim`.

## Проверить на прототипе

- Точный список шаблонов названий по умолчанию (RU и EN) по реальным активностям.
- Как часы делят заплыв на laps: на интервалы между остановками или на отдельные бассейны. От этого зависит, как считать интервалы.
